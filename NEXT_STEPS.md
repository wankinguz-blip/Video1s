# Что делать дальше — 3D-версия в Blender

Файл для продолжения работы в новой сессии. Состояние на 2026-11-14, конец третьей сессии.
Ветка: `vorflux/blender-3d-rework` (от `main`), pull request в `main` открыт.
Чтобы продолжить, достаточно написать: «Продолжай по NEXT_STEPS.md в ветке vorflux/blender-3d-rework».

## 1. Коротко

Сцена, три персонажа с костюмами и хореографией, фейерверки и скрипт рендера готовы и проверены в
песочнице на уменьшенном размере. **Осталось:** полноразмерный рендер на Mac заказчика и просмотр
движения на видео (в песочнице нет видеокарты, 450 кадров там рендерятся около 4 часов).

## 3. Что не проверено

* Полноразмерные кадры (6864 / 11752 / 6240 × 1872) ни разу не рендерились. EEVEE на Metal не проверен.
  Время рендера на Mac неизвестно — его измеряет `scripts/show.sh bench`.
* Движение не просмотрено на видео. Проверено числами, на листах «палочных» фигур и на ключевых
  позах. После первого превью возможны правки хореографии.
* Ветка `setup` для macOS (монтирование dmg, копирование Blender.app в `tools/`) не запускалась.
* Финальное качество (полная плотность травы) проверено только на крупных планах трёх персонажей в 1/4 размера и на
  полноразмерной полосе 512 px у стыка; целый экран в финальном качестве не рендерился.

## 4. Следующие шаги, по порядку

1. **На Mac: проверка и замер.** Выполнить команды из раздела 5 до `bench` включительно. Нужны:
   последние строки `bench` (секунд на кадр и оценка), картинка `out/test/panorama_t02_500.png`.
   Если команда падает — конец файла `out/logs/render.log`.
2. **На Mac: превью.** `scripts/show.sh preview` → `out/preview/VANKING_panorama_preview.mp4`
   (панорама 3107×234, черновое качество, со звуком). Посмотреть движение, попадание в музыку,
   читаемость персонажей. Замечания передать в следующую сессию.
3. **Правки по превью** (если будут). Хореография: `blender/vk/choreo/*.py`; после каждой правки
   запустить `dev/check_choreo.py` (должно быть PASS) и лист фигур `dev/stick_sheet.py` — команды и
   нужный Python см. в разделе 6. Свет: `blender/vk/lighting.py`. Фейерверки: параметры в начале
   `blender/vk/fireworks.py`.
4. **Если `bench` показывает слишком долгий рендер:** `SAMPLES=16` (вдвое быстрее, мягкие тени
   чуть шумнее), `EXTRA="--grass 0.5"` (вдвое меньше травы), `JOBS=2` (два процесса, если хватает
   памяти). Если в логе есть `Shadow buffer full` — уменьшить `shadow_resolution_scale` в
   `blender/vk/lighting.py` или увеличить `scene.eevee.shadow_pool_size`.
5. **Финальный рендер:** `scripts/show.sh final`. Затем на Mac `scripts/show.sh validate` и
   `scripts/show.sh seams` (по минуте каждая) — должны дать PASS и на Metal.
6. **Проверка готовых файлов:** проиграть каждый mp4 пять раз подряд, например
   `ffplay -loop 5 deliverables/VANKING_center_11752x1872.mp4`, и убедиться, что переход 14,97 → 0 с
   не виден и не слышен. Проверить стыки на `VANKING_panorama_preview.mp4`.
7. **Pull request:** ревью, слияние в `main`. После слияния в командах клонирования не нужен
   `--branch`.

Необязательные улучшения, если заказчик попросит: цветной контровой свет на персонажах (сейчас
силуэты отделяет только холодный лунный свет), более высокие холмы, центральный залп ниже верхнего
края кадра (сейчас он на полсекунды обрезается сверху), тени от травы (`--grass-shadows`).

## 5. Команды для Mac

Репозиторий закрытый: для `git clone` нужна авторизация GitHub (например `gh auth login`).

```bash
git clone --branch vorflux/blender-3d-rework https://github.com/wankinguz-blip/Video1s.git
cd Video1s
brew install ffmpeg
scripts/show.sh setup      # скачивает Blender 4.5.16 LTS (arm64) в tools/, не трогает /Applications
scripts/show.sh test       # три пробных кадра в 1/4 размера -> out/test/panorama_t02_500.png
scripts/show.sh bench      # два полноразмерных кадра центрального экрана: время кадра и оценка для final
scripts/show.sh preview    # превью-видео панорамы со звуком -> out/preview/VANKING_panorama_preview.mp4
scripts/show.sh final      # полные кадры трёх экранов + mp4 со звуком -> deliverables/
```

Рендер можно прервать (Ctrl-C) и запустить ту же команду снова: готовые кадры пропускаются.
`scripts/show.sh help` — все команды и переменные. Blender через `brew install --cask blender`
ставить не нужно: версия может отличаться. Если репозиторий уже склонирован: `git pull`.

## 6. Как работать в песочнице

* `scripts/show.sh setup` скачивает Blender в `tools/`. Для рендера без экрана на Linux нужен
  `libegl1` (`apt-get install -y libegl1`); `setup` сообщает, если его нет.
* В системном `python3` нет numpy. Проверки без Blender запускать его Python:

```bash
cd blender
../tools/blender/4.5/python/bin/python3.11 dev/check_choreo.py            # все три должны дать PASS
../tools/blender/4.5/python/bin/python3.11 dev/stick_sheet.py emo ../out/emo.png --from 0 --to 30 --step 0.25 --cols 16
```

* Быстрые команды (подробнее — `blender/README.md`):

```bash
B=tools/blender/blender
# черновая панорама 1/8: около 35 с на кадр
$B -b --factory-startup --python blender/render.py -- --slice pano --scale 0.125 --time 2.5 --out out/peek --samples 4 --quality draft
# крупный план персонажа в сцене: emo | singer | sax
$B -b --factory-startup --python blender/render.py -- --slice singer --scale 0.3 --time 2.5 --out out/peek --samples 6 --quality draft
# лист поз или кадры хореографии на нейтральном свете, без окружения
RES=420 $B -b --factory-startup --python blender/dev/pose_sheet.py -- emo out/poses rest,up front,three,side,back
RES=380 $B -b --factory-startup --python blender/dev/pose_sheet.py -- emo out/poses choreo:1.0,2.0,5.0 front
# сколько весит сцена: время сборки, память, треугольники
$B -b --factory-startup --python blender/dev/scene_stats.py -- --quality final
```

* Песочница — 2 ядра, 8 ГБ, без видеокарты (программный OpenGL). Финальное качество целой панорамы в
  ней не рендерится; узкий срез (`--slice singer --scale 0.25`) — около 2 минут. Увеличить песочницу
  платформа не позволила.

## 7. Правила, которые нельзя нарушать

* Никакого композитора, bloom, screen-space эффектов (SSS, SSR, преломление) и объёмного тумана: они
  зависят от границ кадра и дадут разную картинку на соседних экранах. Свечение — геометрия с
  аддитивным материалом.
* Всё, что движется, — периодическая функция с периодом 15 с. Никакой физики, симуляций и состояния
  между кадрами. Шейдеры берут время из группы узлов `VK_Time` (`util.time_node`).
* Положение камеры одинаково для всех срезов. Меняются только сдвиг объектива и разрешение.
* Контракты между модулями: `rig.HEAD` (точки головы), `propspec.py` (микрофон, саксофон),
  `pose(t) -> rig.Pose` в хореографии, `extra_bones / build / update` в `mole.py`, объёмы столкновений
  в `dev/check_choreo.py` (шляпы, чёлка). Менять только согласованно с обеих сторон.
* Каждое изменение сразу коммитить и пушить; после каждого этапа обновлять `PROGRESS.md` и этот файл.
